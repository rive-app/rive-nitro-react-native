# Repository guidelines

## Comments

- Don't add comments unless they're needed. The code should read on its own; prefer
  clear names and structure over narration.
- Never write comments that just restate what the code does.
- A comment earns its place only by adding what the code can't show: *why* a choice
  was made, a non-obvious constraint, a gotcha, or a link to context (issue/PR).
- Comments must be accurate. A wrong or stale comment is worse than none — keep them
  in sync with the code or delete them.
